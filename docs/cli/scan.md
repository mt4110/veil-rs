# veil scan

Status: `reference`

通常CLIの読取りスキャンです。初回利用は [チュートリアル](getting-started.md)、結果の扱いは [利用ガイドライン](usage-guidelines.md)。

```bash
veil scan [OPTIONS] [PATHS]...
```

| オプション | 振る舞い |
| --- | --- |
| `[PATHS]...` | 既定は `.`。存在するファイル・ディレクトリを指定。欠損パスはエラー |
| `--format <FORMAT>` | `text`（既定）・`json`・`html`・`table`・`md`・`markdown`。最小ビルドではtableはtextへフォールバック |
| `--fail-on-findings <N>` | **新規検知数がN以上**なら終了コード1。1件以上なら `1`。`0` は入力エラー（終了コード2） |
| `--fail-on-score <SCORE>` | 新規検知に指定スコア以上があれば1 |
| `--fail-on-severity <LEVEL>` | 新規検知に指定重大度以上があれば1 |
| `--baseline <PATH>` | baselineに一致する既存検知を抑制。抑制後の件数が0でも収集時の上限到達は保持 |
| `--write-baseline <PATH>` | 上限打ち切り・サイズ上限・読込みエラーなら2で保存せず、既存ファイルを保全。完全なスキャンなら保存（同名ファイルを上書き）。`--baseline` / `--interactive` と同時指定不可 |
| `--limit <N>` | 検知数上限。通常の非対話スキャンで上限到達は2。`0` は無制限。baseline作成も保存前に拒否 |
| `--mask-mode <MODE>` | `redact`・`partial`・`plain`。`plain` は生データを許可 |
| `--unsafe` | 生データ表示を許可。共有用に使わない |
| `--no-color` | 色を無効にする |
| `--staged` | Gitインデックスの対象を検査 |
| `--commit <SHA>` | 第1親との差分にある追加・変更ファイルを検査。最初のコミットは空ツリーとの差分で検査 |
| `--since <TIME>` | 指定時刻以降の各コミットの追加・変更ファイルを検査。最初のコミットも対象 |
| `--config <PATH>` | 存在する通常の設定ファイルを指定。存在しない指定は終了2 |

全オプションは `veil scan --help` で確認します。組織・ユーザー・プロジェクト設定と環境変数も適用されます。
ファイル数上限は `core.max_file_count`、サイズ上限は `core.max_file_size`、検知上限は `output.max_findings` でも設定できます。

## ステージ済み変更と通常ファイルの違い

`scan --staged` はGitプロジェクト内で実行し、HEADに対する追加・変更ファイルのインデックス内の内容全体を読みます。作業ファイルの修正だけでは変わらず、修正後の `git add` が必要です。未ステージ・未追跡・変更のないファイルやGit履歴全体は対象ではありません。空のステージも終了コード0になります。
`.gitignore` による対象外やバイナリ等のスキップもあるため、0だけでは点検範囲を保証しません。今回のRCでは、ignore対象を `git add -f` した場合も対象外になります。疑わしいテキストは通常スキャンでファイルを明示して確認してください。
[初回スキャンから次回利用まで](getting-started.md#commit前にステージ済み変更を点検する)に、対象一覧確認・点検・修正・再ステージの手順を記載しています。

## 出力と失敗判定

設定がない既定のスキャンは、検知だけでは失敗しません。CIには失敗条件を明示します。

```bash
veil scan src --fail-on-findings 1
veil scan src --format json --fail-on-severity High
```

JSONは `veil-v1` の単一オブジェクトを標準出力へ返し、診断は標準エラーへ返します。実行エラー時はJSONがない場合があります。
終了コードは0（失敗条件非該当）、1（検知条件該当）、2（実行エラー・上限打ち切り）。
無視・バイナリによるスキップがあるため、0だけでは全件スキャンを保証しません。
baseline適用と上限を併用した通常の非対話スキャンでは、新規検知0件でも上限到達は2です。対話モードは不完全な結果をレビュー前に終了コード2で拒否します。Git blobやHEADツリー等を読めない検査はエラー2となり、baselineを保存しません。サブモジュールへのGitlinkは親リポジトリのblobではないため、明示的なスキップとして集計します。修正の [検証範囲](../ci/oss-cli-release.md#公開前の必須課題) を確認し、CIは非対話で実行してください。

レポートは対象の外へ保存します。既存出力を保全する場合は新しいファイル名を指定します。

```bash
veil scan src --format json > reports/scan.json
veil scan src --format html > reports/scan.html
```

`src` と既存の `reports` を自分のパスへ置き換えてください。baseline作成も上限到達時は終了コード2で拒否し、部分結果を保存せず既存ファイルを保全します。
通常スキャンのJSON契約は [こちら](../json-schema.md)。GitのHTTPS/SSHトランスポートは通常CLIに含まれず、履歴検査はローカルリポジトリが対象です。

## テキストとignoreの境界

通常ファイル・Gitのcommit/history/staged入力はUTF-8テキストを検査する。先頭8 KiBにNULがある入力はバイナリとして除外する。NULがなくUTF-8へ変換できないGit入力は読取り異常として終了2にし、不完全なbaselineを保存しない。UTF-16復号、XML文字参照の展開、画像・動画の内容検査は行わない。

行のignore指定は、引用符（single/double/backtick）の外にある `#` または `//` コメントの先頭へ1つ置く。`veil:ignore` は行全体、`veil:ignore=rule.id` はそのIDの完全一致だけを抑制する。理由は空白で区切って後ろへ書ける。文字列内の指定、IDの前方一致、コメントの途中の指定は抑制しない。これは行単位の保守的な判定で、全言語のraw文字列・複数行構文を解析する機能ではない。認識できない指定は検査を継続する。

対話プレビューの変更前行は全文を隠し、変更後はスキャン時のマスキング済みsnippetを表示する。生出力を明示した場合は変更後も生値を含み得るため、共有には使わない。

## 独立したGit履歴コマンド

`veil --config project.toml git scan HEAD~1..HEAD` は、通常scanと同じ有効設定・ローカルルールを使い、範囲内の各コミットを第1親と比較して追加行を検出する。`HEAD` 単独指定はそのコミットから到達する履歴全体で、`scan --commit HEAD` の一コミット検査とは異なる。`--pr` はupstream/origin/main/origin/masterから範囲を選ぶ。Gitのfetchや外部通信は行わない。

検出前に変更先blob全体のUTF-8とサイズを検査する。不正UTF-8・サイズ上限・範囲全体の変更先blob件数上限・検知上限は終了2。NULを含むバイナリ、削除、submoduleのGitlinkは対象外。検出対象は追加行のため、終了0でも既存行の秘密がない保証にはならない。正常完了時は検知があっても終了0で、通常scanの `--fail-on-*` やJSON/baseline機能はこの補助コマンドにはない。

これらの修正は公開済みrc.2のZIPに含まれる。rc.1の既存ZIPには反映されない。

## Gitが選ぶインデックス（現行ソースの修正）

`scan --staged` は通常インデックス、または `GIT_INDEX_FILE` が選ぶ別インデックスの内容を読みます。相対パスは実行ディレクトリを基準に扱い、Gitの部分コミット用インデックスも反映します。検査は読取りだけで、通常・別インデックスや作業ファイルを書き換えません。通常インデックスがない最初のコミット前の状態は従来どおり扱います。

明示された `GIT_INDEX_FILE` が空・欠損・ディレクトリ・不正なインデックスなら終了2です。通常インデックスへフォールバックして成功扱いにせず、baselineも作成・上書きしません。

この修正は公開済みrc.2と旧rc.3候補（配布元04745e7）のZIPには入っていません。公開済みM1入りrc.3以降では修正済みです。旧候補のCLIで別インデックスの検査を保証しません。[生成フックの条件](README.md#コミット前フック現行ソースの修正)も確認してください。


## 氏名ルールの限定的な非人物文脈（現行ソース）

`pii.person.name.keyword` は、YAMLステップの完全な処理名 `Check formatting` / `Run clippy` と、説明文の複合語 `container-name mapping` を人物名として報告しません。判定はその候補だけに適用し、同じ行の別の人物名・認証情報・IPv4は引き続き検査します。ファイル全体やすべての `name` 項目を除外する仕様ではありません。他の任意の処理名まで一般化はしていません。

引用符付きの処理名は単一・二重引用符の一致を確認して扱い、未閉鎖の引用符は抑制しません。元の値が行末または空白で始まるコメントまでで終わることも確認し、処理名の後に追加文字が続く値は抑制しません。複合語に続いて同じ候補内に別の人物名ラベルがある場合も抑制しません。

この変更は公開済み0.21.0-rc.3のZIPには含まれません。修正を含む[0.21.0正式版](https://github.com/mt4110/veil-rs/releases/tag/v0.21.0)は公開済みです。テスト用・ループバックIPv4の一律除外も行いません。

## 開発時の文書・コード文脈の限定除外（未リリース）

現行ソースでは、小文字の `port/name mapping` に `and` / `or` / `for` / `to` / `is` が続く説明文を氏名候補から除外します。`published-port/name mapping` のようなハイフン区切りも対象です。後続の別の氏名ラベルがあれば候補を保持し、大文字を含む人物名や通常の `Name:` 表記には適用しません。

`pii.id.customer_member.keyword` は、Rustの `matches!` で `.user_id()` の結果とUID変数を `Some` の組として比較する限定的な式を、ID値の記載として報告しません。式全体が該当する場合だけ適用し、引用符付きの値、コメント、別の顧客／会員IDラベルがある行は除外しません。通常の顧客番号・会員ID・ユーザーIDは引き続き検査します。

これら2件の追加修正は0.22.1の準備ソースに含まれ、公開済み0.22.0には含まれません。テスト用IPv4の一律除外やルールの無効化は行いません。
