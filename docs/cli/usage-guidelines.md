# 利用・結果共有のガイドライン

Status: `reference`

## 対象と結果を確認する

まず [チュートリアル](getting-started.md)を使い、実プロジェクトでは存在するディレクトリを明示します。
結果のルールIDと位置を確認し、誤検知か、失効・修正すべき秘密かを判断してください。重大度やスコアは優先順位の参考で、実際の被害や悪用の証明ではありません。

- `0`: 指定された失敗条件に該当しない。検知がある場合や、無視・バイナリによるスキップがある場合も含む。
- `1`: 件数・重大度・スコアのいずれかの失敗条件に該当する。
- `2`: 実行エラー、または検知・ファイル数上限による打ち切り。

「1件以上で失敗」は `--fail-on-findings 1`。件数条件は指定値以上であり、`0` は入力エラーで終了コード2になります。
通常の非対話スキャンでは、baselineで既知の検知がすべて抑制されても、収集時の上限到達は終了コード2として扱います。対話モードでも不完全な結果はレビュー前に2で拒否し、Git読取り失敗時はbaselineを保存しません。`--interactive` とbaseline作成の同時指定は引数エラー2です。[修正の検証範囲](../ci/oss-cli-release.md#公開前の必須課題) を確認し、CIは非対話で実行します。
JSONの上限フラグとファイル数も確認します。エラー時にはJSONが出ない場合があるため、標準エラーと終了コードを一緒に扱います。
上限を無制限に増やす前に対象・除外を見直し、除外した範囲も記録します。baseline作成は検知・ファイル数上限に達すると終了コード2で拒否し、部分結果を保存せず既存baselineを保全します。

## 保存・共有する前に確認する

既定のマスキングは、検知した部分への処理です。未知の秘密、パス・ファイル名、Gitの作者、同じ行のその他の情報等が残ることがあります。
JSONの既定出力は一致値と前後の行を秘匿しますが、レポート全体の匿名化や完全な秘密除去を保証しません。
`--unsafe`、`--mask-mode plain` は生データ表示を許可します。共有用の出力では使わないでください。設定ファイルの `output.mask_mode = "plain"` は禁止され、redactを同時指定しても終了コード2で拒否します。
table形式のMatch列は、明示的に生出力を許可しない限り `<REDACTED>` を表示します。設定ファイルから生出力は許可できません。公開済み0.21.0-rc.1のZIPにはこの修正が入っておらず、table形式はredact指定でも生の一致値を表示します。公開済みrc.2のZIPでは修正済みなので、rc.2を取得してください。
必要に応じて `--mask-mode redact` で検知部分を全面マスキングし、それでも共有前の内容確認は行います。

レポートを対象ディレクトリの外へ保存します。公開Issue・CI artifactへ添付する前に、最小限のルールID・件数・架空の再現例へ絞ってください。
本物の秘密を検知した場合は、出力を隠すだけでなく該当サービスで失効・ローテーションし、ソースと履歴への残存を確認します。

## baselineを承認と混同しない

baselineは照合した検知を出力・失敗判定から抑制する仕組みです。リスク承認、秘密の失効、修正完了を表しません。
パス・行・ルール・マスキング後の行から照合するため、生の秘密が変わっても同じ検知として扱われる場合があります。
ファイルを移動した際などに再検知されても、内容をレビューせずbaselineへ追加しないでください。
baselineには位置・ルール・重大度等が含まれます。保存・公開範囲をレビューしてください。[baseline詳細](../baseline/usage.md)。

## 設定と書込み操作

設定・環境変数は検知対象と終了条件を変えます。`veil config check` で検証し、`veil config dump` の表示内容をローカルで確認します。
組み込みルールの利用には初期化や `update` は不要です。ローカルRulePackの有効ルールを `veil rules list` で確認します。

通常の `scan` は入力ファイルを書き換えません。`--write-baseline`、レポートへのリダイレクト、`init`、`pre-commit init`、`mask` は保存先を確認する操作です。
既存baselineへの上書きや `mask` の実書換え前にはバックアップと差分を確認し、`mask --dry-run` を先に使ってください。設定の構文・検証エラーはdry-run/実書換えとも終了2で拒否し、入力やバックアップを書き換えません。TOML構文エラーの診断には本文・設定値を含めず、行・列だけを表示します。パス等のメタデータは匿名化されません。
`scan`・`filter`・`mask`・`git scan` は同じ有効設定と組み込み/カスタム/ローカルRulePackのルールを読み込む。明示 `--config` が存在しない、または通常ファイルでない場合は終了2。設定を指定しない場合、`veil.toml` がなくても既定設定で利用できる。

`mask` は通常ファイルを一つ以上明示する操作で、ディレクトリ走査は行わない。`core.ignore` に一致する入力と先頭8 KiBにNULを含むバイナリは対象外。不正UTF-8・サイズ/件数/検知上限・設定/RulePackエラーを事前確認し、失敗した場合は入力とbackupを書き換えない。検知上限に達した場合は、通常scanと同様に終了2で拒否する。

LF/CRLFの混在、末尾改行の有無、ファイル権限を保持する。重複入力・symlink・読取り専用の書換え対象・空/区切り文字を含むbackup suffixを拒否する。backupは元のバイト列を保存し、既存ファイルや壊れたsymlinkを上書きしない。全入力の事前確認後、各ファイルを一時ファイルから置換し、その直前に入力が変わっていないか再確認する。途中のI/O失敗では先に成功したファイルや作成したbackupが残る場合がある。複数ファイルの一括ロールバックや他プロセスとの排他は保証しないため、実行後も差分を確認する。

通常CLIにはGuardianや外部ルールダウンロードは含まれません。

## 不具合を報告する

CLIのバージョン、OS、使用したオプション、期待した終了コードと実際の終了コードを記載します。
本物の認証情報や組織の設定全体を添付せず、架空の最小入力で再現してください。
開発参加は [開発ガイド](../DEVELOPMENT.md)、対応範囲は [アーキテクチャ](../architecture/local-oss.md)を参照します。

## 公開RCと修正済みソースの区別

公開済み0.21.0-rc.1にはtableの生値出力に加え、対話プレビューの複数秘密値露出、Git入力の不正UTF-8の正常スキップ、ignoreの部分一致、TOML診断の本文露出、maskの設定エラー時の既定設定への復帰が残ります。このソースの修正は既存ZIPを更新しません。rc.2へ移行するまでrc.1では非対話のtext/JSONとredactを使い、設定エラー全文を共有せず、設定確認に失敗した状態でmaskを実行しないでください。Gitの終了0だけで全対象のUTF-8読取りを保証しないことにも注意してください。

旧rc.1には、明示した存在しない設定の既定設定への復帰、maskのカスタム/RulePackルール未適用・改行変更・直接上書き、`git scan` の `--config` 未反映・不正UTF-8除外も残る。ここで説明した追加修正も既存ZIPには入らない。rc.1の補助書換え・履歴操作へrc.2の修正を適用済みと扱わない。

公開済み0.21.0-rc.2は、上記rc.1の制限に対するmainの修正を含む。rc.1の既存ZIPは変更せず、rc.2のZIPを別に検証・公開した。ファイル単位のmask置換、検出の誤検知/見逃し、パス等の非匿名化、macOS ad-hoc署名の制限は引き続き適用される。
